## Findings considered and rejected (do not re-audit)

- **Stored XSS in web view**: `viewer.ts` injects sanitized `email.html` unescaped, but ships a strict CSP (`script-src 'none'`), strips event handlers and `style`/`javascript:` at sanitize time, and sets `nosniff`/`X-Frame-Options`. Defense-in-depth holds. (Plan 003 adds tests to keep it that way.)
- **JWT `alg`-confusion / `alg:none` bypass**: `verifyToken` ignores the JWT header and always HMAC-verifies with the server secret, so a forged `alg` cannot bypass verification. Not exploitable.
- **Public feed/email read access** (`/feeds/:id`, `/feeds/:id/view/:emailId`): by-design shareable permalinks per ARCHITECTURE.md; feed/email ids are `nanoid`, not enumerable.
- **`cors: access-control-allow-origin: *`**: this is a public Bearer-token API with no cookie auth; wildcard CORS is appropriate.
- **Failing lint**: a transient `bun run lint` failure seen once during the audit did not reproduce — `bun run lint` and `bun run check` both pass cleanly and repeatably. No action needed.

## Documented findings NOT turned into plans

- **`updateFeedEmailIndex` non-atomic read-modify-write** (`routes/webhook.ts:82-112`): concurrent webhooks for the same feed can drop an entry from the email index (both email blobs are still stored; only the index list loses one). MED confidence, MED risk. Deferred because the fix is a design decision — either move the per-feed email index into a Durable Object (consistent, more moving parts) or accept the rare loss. Worth a design spike before a code plan.
- **Direction — ARCHITECTURE.md describes unbuilt systems** (D1 storage, LLM pattern-learning fallback). Storage is entirely KV and link extraction is pure regex (`lib/patterns.ts`). Recommend splitting the doc into "current" vs "planned" so contributors aren't misled. Documentation task, not a code plan.
- **Direction — no email-retention policy surfaced**: the 200-email/feed cap (`routes/webhook.ts:11`) silently drops the oldest emails. If retention becomes a product promise, make it explicit and observable.
